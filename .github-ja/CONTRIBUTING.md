# コントリビューションガイドライン

バグ報告、新機能の提案、ドキュメントの改善など、コントリビュートの際は以下のガイドラインに従ってください。

## Issueドリブン開発について

本プロジェクトは「Issueドリブン」開発手法を採用しています。Issueドリブンとは、バグ修正・新機能追加・ドキュメント改善など、すべての作業をGitHub Issueとして管理し、Issue単位で作業を進める方法です。これにより、各タスクの目的・背景・進捗が明確になり、チーム内での情報共有やレビューが円滑に行えます。

- 作業を始める前に、必ずIssueを作成または確認してください。
- ブランチは必ずIssueと紐付けてください。（例: `feat/123-newFeature`）
- プルリクエストを作成する際は、必ずIssueとリンクさせてください。プルリクエストとIssueの紐付け方法については[公式ドキュメント](https://docs.github.com/ja/issues/tracking-your-work-with-issues/using-issues/linking-a-pull-request-to-an-issue)を参照してください。

## コミットについて

- 1コミットにつき1つの機能追加またはバグ修正だけを含めてください。
- 文法エラーが無い状態でコミットしてください。
- コミットメッセージの1行目は`{verb} {summary}`の形式で記述してください。
  - `Add user profile page`
  - `Fix login bug`
  - `Update README.md`
- コミットメッセージの2行目にはそのコミットの詳細を記述してください。

## ブランチ戦略

### ブランチ命名規則

| ブランチ種別 | 目的                             | 命名例                                    |
| ------------ | -------------------------------- | ----------------------------------------- |
| Feature      | 新機能の実装                     | `feat/{IssueNum}-{featureName}`           |
| Bugfix       | バグ修正                         | `fix/{IssueNum}-{bugName}`                |
| Cherry-pick  | 他ブランチから特定コミットを適用 | `cherrypick/{sourceBranch}-{description}` |
| Sandbox      | 試験やプロトタイピング           | `sandbox/{commitId}-{userName}`           |

- `main`ブランチ：本番用の安定したブランチです。
- 開発時は、目的に応じて`main`から新しいブランチを作成してください。
  - Feature: `feat`<br>
    新機能実装用のブランチです。
  - Bugfix: `fix`<br>
    バグ修正用のブランチです。
  - Cherry-pick: `cherrypick`<br>
    特定コミットのみを他ブランチへ適用するためのブランチです。
  - Sandbox: `sandbox`<br>
    新機能の試験やプロトタイピング用のブランチです。

### ブランチのマージルール

- 作業ブランチ（`feat`や`fix`など）から`main`ブランチへのプルリクエストを作成してからマージしてください。
- `main`ブランチへの直接コミットやマージは禁止です。
- マージ前に必ずコンフリクトを解消してください。

## AIの利用について

コントリビュートの際にAIツール（コード生成、文章作成支援など）を利用しても構いませんが、その内容に責任を持てる場合にのみ利用してください。

- AIが生成した内容（コード、ドキュメント、Issue、プルリクエスト）は、提出前に必ず確認・理解・検証してください。
- 自分で説明や保守ができない内容は提出しないでください。
- AIが生成した内容がライセンスに違反していないか、機密情報を含んでいないかを確認してください。
- 提出した内容に責任を負うのはAIではなく、あなた自身です。

## コントリビュートの流れ

1. 作業開始前に、目的や背景を記載したIssueを作成または確認してください。
2. `main`ブランチから作業用ブランチを作成し、Issueに沿った名前（例: `feat/123-featureName`）にしてください。
3. 作業が完了したら、`main`をターゲットにプルリクエストを作成してください。
4. レビュー中のフィードバックに対応し、進捗や変更点はIssueにも反映してください。
5. メンテナーによる承認後、プルリクエストは`main`ブランチへマージされ、作業ブランチは削除、プルリクエストはクローズされます。
